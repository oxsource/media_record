# Feature Specification: 模拟行车记录仪录制（Dashcam Simulated Recording）

**Feature Branch**: `002-dashcam-sim-recording`

**Created**: 2026-08-18

**Status**: Draft

**Input**: User description: "以一张图片作为背景模拟摄像头数据输入，设计布局绘制时间戳于其上模拟行车记录仪画面，然后编码输出录制视频，默认10秒"

## Clarifications

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 一键生成模拟行车记录仪视频（Priority: P1）

开发者运行录制入口，系统以一张图片模拟摄像头输入，将其排布为视频画面，并在画面角落实时绘制录制时间戳（随时间逐帧更新，模拟行车记录仪 OSD），随后编码并输出一段视频文件；默认录制 10 秒后自动结束。

**Why this priority**: 这是本 feature 的核心价值——首次打通"输入 → 画面组合 → OSD 叠加 → 编码 → 落盘"的端到端录制闭环，验证工程骨架可产出真实可播放的录制产物。

**Independent Test**: 以默认配置运行录制入口，等待其自动结束，检查输出的视频文件存在、可播放、时长约等于默认 10 秒，且画面中含输入图片与逐帧更新的时间戳。

**Acceptance Scenarios**:

1. **Given** 输入图片存在且格式受支持，**When** 启动录制，**Then** 系统持续输出模拟画面并在约 10 秒后自动结束，退出码为 0
2. **Given** 录制已结束，**When** 检查输出文件，**Then** 存在一个可播放的视频文件，播放时长与默认 10 秒一致（允许较小误差）
3. **Given** 录制已结束，**When** 逐帧查看输出视频，**Then** 画面主体为输入图片，且角落叠加了随时间递增的时间戳文字

---

### User Story 2 - 可配置的录制参数（Priority: Deferred）

录制参数配置（录制时长 / 输入图片 / 输出位置 / 时间戳格式与位置）**不在本提案范围**，由后续提案实现；本期录制入口以默认值运行，不提供参数配置面。

> 已按 Clarifications 2026-08-18 的澄清决定推迟本故事。

---

### User Story 3 - 录制失败可定位（Priority: P3）

当输入图片缺失 / 格式不支持、输出位置不可写、或编码失败时，系统给出清晰可读的错误信息，能定位到具体原因，而不会崩溃或无意义报错。

**Why this priority**: 清晰的失败提示保证该工具在日常开发与 CI 中可稳定使用，符合工程骨架一贯的失败可定位原则。

**Independent Test**: 分别构造输入缺失、输出不可写等失败场景运行，检查错误信息是否指明具体原因。

**Acceptance Scenarios**:

1. **Given** 输入图片路径不存在，**When** 运行录制，**Then** 输出明确错误并退出非零，错误信息包含该路径
2. **Given** 输出位置不可写，**When** 运行录制，**Then** 输出明确错误并退出非零，错误信息包含该路径
3. **Given** 编码过程发生失败，**When** 运行录制，**Then** 输出明确错误并退出非零，不产生残缺产物

---

### Edge Cases

- 输入图片缺失或路径无效：给出可定位错误，退出非零。
- 输入图片格式不受支持：给出可定位错误。
- 输出目录不存在或不可写：给出可定位错误。
- 输出文件已存在：覆盖并继续，并在日志中提示已覆盖旧文件。
- 编码中断 / 资源不足：不产生损坏的半成品文件。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 系统 MUST 接受一张静态图片作为模拟摄像头输入。
- **FR-002**: 系统 MUST 将输入图片按既定布局排布为录制画面的视频帧序列。
- **FR-003**: 系统 MUST 在画面固定位置绘制录制时间戳，时间戳 MUST 显示录制时刻的真实日期与时间（真实时钟），并随时间自然递增，模拟行车记录仪画面。
- **FR-004**: 系统 MUST 将生成的视频帧序列编码为通用、可播放的视频格式并写入输出文件。
- **FR-005**: 系统 MUST 默认录制 10 秒后自动结束录制并正常退出（时长可配置能力留待后续提案）。
- **FR-006**: 系统 MUST 使用内置默认输入图片与默认输出位置完成录制（输入/输出可配置能力留待后续提案）。
- **FR-007**: 系统 MUST 使用默认的时间戳显示格式与位置绘制时间戳（格式/位置可配置能力留待后续提案）。
- **FR-008**: 输入缺失 / 格式不支持 / 输出不可写 / 编码失败时，系统 MUST 给出可定位到具体原因的清晰错误并退出非零。
- **FR-009**: 系统 MUST 在结束时不残留损坏的半成品文件。
- **FR-010**: 本期 MUST 将记录仪 pipeline 引用的 7 类节点（画面输入 / 信号源 / 多画面布局 / OSD 叠加 / 视频编码 / 录制 / 封装输出）实现为可运行的真实实现；其余未引用的节点类型（音频编码 / 推流 / 预览）本期仅保留骨架，不做功能实现。

### Key Entities *(include if feature involves data)*

- **模拟视频帧（Simulated Frame）**: 由输入图片按布局排布而成、可叠加 OSD 的单帧画面，构成视频序列的最小单元。
- **时间戳叠加层（Timestamp Overlay）**: 绘制在帧上的录制时间文字，含格式与位置属性，随录制进度更新。
- **录制会话（Recording Session）**: 一次录制的运行状态，含时长、帧率、输出目标与结果状态。
- **输出视频文件（Output Video）**: 录制产物，可被常见播放器播放，时长与默认时长一致。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 默认配置下，录制入口在约 10 秒内自动结束并退出码为 0，产出可播放的视频文件。
- **SC-002**: 输出视频的播放时长与默认 10 秒一致（误差 ≤ 5%）。
- **SC-003**: 输出视频画面包含输入图片主体，且时间戳在录制期间逐帧递增、清晰可辨。
- **SC-004**: 自动化验证（一键验证）能覆盖上述三条：编译、录制、产物检查全部通过。
- **SC-005**: 任一失败场景（输入缺失 / 输出不可写 / 编码失败）均返回非零退出码并输出可定位错误。

## Assumptions

- 本期使用工程内置的一张默认示例图片作为模拟输入（常见图片格式，如 JPEG / PNG）；由使用方指定输入图片的能力留待后续提案。
- 输出视频采用通用容器与编码（如 MP4 + H.264），可被主流播放器直接播放。
- 默认帧率取 30fps；默认分辨率跟随输入图片。
- 时间戳默认格式为"日期 时:分:秒"，内容为录制时刻的真实日期时间（真实时钟），默认位置为画面一角（如右下角）。
- 默认输出位置为工程约定的产物目录（如 `out/`）下的固定文件名。
- 录制参数的可配置能力（时长 / 输入图片 / 输出位置 / 时间戳格式与位置）不在本提案范围，由后续提案实现；本期均使用默认值。
- 本 feature 不实现真实摄像头采集、不实现多路拼接业务逻辑；仅以单张图片模拟单路输入，为后续真实录制提供可运行基线。
- 节点实现范围限定为记录仪 pipeline 引用的 7 类节点；音频编码 / 推流 / 预览 3 类节点不在本期范围，由后续 feature 实现。
- 录制为同步、有限时长的批处理行为；不支持暂停/续录/事件标记等交互式能力。
- 录制节点本期实现为"单会话单分段"：一次录制产出一个分段文件；缓存池 / 多分段切换 / 防抖等能力留待真实录制 feature。
